คือ Linked List ที่แต่ละ Node เก็บ pointer **สองตัว** แทนที่จะเป็นตัวเดียวเหมือน Singly Linked List 
1. **Data** — ค่าข้อมูล
2. **Next** — pointer ไปยัง Node ถัดไป
3. **Prev** — pointer ไปยัง Node ก่อนหน้า

![[Pasted image 20260926185801.png]]
การมี pointer ทั้งสองทิศทางทำให้เรา**เดินย้อนกลับ (backward traversal)** ได้ และที่สำคัญกว่านั้นคือ **เมื่อเรามี reference ไปยัง Node ใดๆ อยู่แล้ว เราสามารถลบหรือแทรกข้างๆ Node นั้นได้ในเวลา O(1) โดยไม่ต้องเดินหา Node ก่อนหน้า** ซึ่งเป็นจุดอ่อนที่สุดของ SLL

### แนวคิดและปัญหาที่แก้จากเดิม
**Singly Linked List** แต่ละโหนดรู้จักแค่ "โหนดถัดไป" ทำให้มีปัญหา:
- ถอยหลังไม่ได้ ถ้าอยากรู้ว่าโหนดก่อนหน้าคือใคร ต้องเดินวนใหม่จากหัวลิสต์
- ลบโหนดที่ถือตัวชี้อยู่แล้วยาก เพราะต้องหาโหนดก่อนหน้าให้เจอก่อน

**Doubly Linked List** แก้ปัญหานี้โดยให้แต่ละโหนดเก็บตัวชี้ **2 ตัว** คือ `prev` (ตัวก่อนหน้า) และ `next` (ตัวถัดไป)

```
 null ← [A] ⇄ [B] ⇄ [C] ⇄ [D] → null
        head                tail
```

#### เปรียบเทียบกับชีวิตจริง

- **ปุ่ม Back / Forward ของเว็บเบราว์เซอร์**: หน้าเว็บที่เปิดไล่กันมาเป็นโหนด กด Back คือใช้ `prev` กด Forward คือใช้ `next`
- **เพลย์ลิสต์เพลง**: กดเพลงก่อนหน้าหรือเพลงถัดไปได้ง่ายๆ
- **รถไฟที่วิ่งไป-กลับ**: จากสถานีหนึ่งไปได้ทั้งสถานีก่อนและสถานีถัดไป

#### ทำงานอย่างไร (ทีละขั้น)
โหนดหนึ่งตัวหน้าตาแบบนี้:

```python
class Node:
    def __init__(self, data):
        self.data = data
        self.prev = None   # ชี้ไปโหนดก่อนหน้า
        self.next = None   # ชี้ไปโหนดถัดไป
```

**การแทรกโหนดใหม่ `X` ระหว่าง `A` กับ `B`:**

1. ให้ `X.prev` ชี้ไปที่ `A`
2. ให้ `X.next` ชี้ไปที่ `B`
3. ให้ `A.next` ชี้ไปที่ `X`
4. ให้ `B.prev` ชี้ไปที่ `X`

เหมือนต่อโซ่ที่ต้อง "จับมือ" ทั้งสองฝั่ง ถ้าลืมข้อใดข้อหนึ่งโซ่จะขาด!

**การลบโหนด `X` (ที่อยู่ระหว่าง `A` กับ `B`):**

1. ให้ `A.next` ชี้ไปที่ `B` (ข้าม X)
2. ให้ `B.prev` ชี้ไปที่ `A`
3. ปล่อยโหนด X ทิ้ง

สังเกตว่าถ้ามีตัวชี้ไปที่ X อยู่แล้ว เราลบได้ทันทีโดยไม่ต้องวนหาโหนดก่อนหน้า (เร็ว O(1))

#### ข้อดี และข้อเสีย

|ข้อดี ✅|ข้อเสีย ❌|
|---|---|
|เดินได้ทั้งไปหน้าและถอยหลัง|ใช้หน่วยความจำมากขึ้น (ต้องเก็บตัวชี้ 2 ตัวต่อโหนด)|
|ลบโหนดที่ถือตัวชี้อยู่ได้เร็ว O(1)|โค้ดซับซ้อนขึ้น ต้องจัดการตัวชี้ 2 ทิศทางให้ถูกต้อง|
|แทรก/ลบที่หัวและท้ายเร็ว|ยังค้นหาข้อมูลต้องไล่ทีละตัว O(n)|

> 💡 **ปัญหาที่ยังเหลือ:** ถึงจะเดินได้สองทาง แต่ค้นหาข้อมูลยังต้องไล่ทีละโหนด ช้ามากถ้าข้อมูลเยอะ นำไปสู่โครงสร้างถัดไป... นั้นคือ [[Skip List]]
