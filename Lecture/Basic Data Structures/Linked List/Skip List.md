ทั้ง [[Singly Linked Lists]] และ[[ Doubly Linked List ]]ค้นหาช้า เพราะต้องเดินทีละโหนดจากหัว แม้ข้อมูลจะเรียงลำดับไว้แล้วก็ตาม ไม่สามารถ "กระโดดข้าม" แบบที่ Binary Search ทำกับอาร์เรย์ได้

**Skip List** แก้ปัญหานี้โดยสร้าง "ทางด่วน" หลายชั้นซ้อนกันเหนือลิสต์ปกติ เพื่อให้กระโดดข้ามโหนดได้

### เปรียบเทียบกับชีวิตจริง
![[Pasted image 20261001081607.png|392]]
**รถไฟฟ้าสายต่างๆ:** ลองนึกถึงการเดินทางข้ามเมือง
- **ชั้นล่างสุด** = รถธรรมดาที่จอดทุกสถานี
- **ชั้นกลาง** = รถด่วนที่จอดเฉพาะสถานีสำคัญ
- **ชั้นบนสุด** = รถด่วนพิเศษที่จอดแค่ไม่กี่สถานีใหญ่

ถ้าจะไปสถานีที่ไกลมาก เราขึ้นรถด่วนพิเศษก่อน พอใกล้ถึงก็ลงมาต่อรถด่วน แล้วค่อยลงมาต่อรถธรรมดาเพื่อไปถึงสถานีปลายทางเป๊ะๆ

#### ทำงานอย่างไร (ทีละขั้น)

โครงสร้างหน้าตาแบบนี้ (ข้อมูลเรียงจากน้อยไปมาก):

```
ชั้น 3:  HEAD ──────────────────────→ 50 ─────────────→ NIL
ชั้น 2:  HEAD ───────→ 20 ──────────→ 50 ──────→ 70 ──→ NIL
ชั้น 1:  HEAD → 10 → 20 → 30 → 40 → 50 → 60 → 70 → 80 → NIL
```

**การค้นหา (เช่น หาเลข 60):**

1. เริ่มที่ชั้นบนสุดของ HEAD
2. มองตัวถัดไปในชั้นนั้น: ถ้ายัง **ไม่เกิน** เป้าหมาย → เดินไปข้างหน้า
3. ถ้าตัวถัดไป **เกิน** เป้าหมาย (หรือเป็น NIL) → **ลงชั้นล่าง** แล้วทำซ้ำ
4. ทำไปจนถึงชั้นล่างสุดและเจอเป้าหมาย

จากตัวอย่าง: เริ่มชั้น 3 → ไปที่ 50 (ถัดไปคือ NIL ลงชั้น 2) → ถัดไปคือ 70 เกินไป ลงชั้น 1 → ไปที่ 60 เจอแล้ว! 🎉

**การแทรกข้อมูลใหม่ (หัวใจคือ "โยนเหรียญ"):**
1. ค้นหาตำแหน่งที่ข้อมูลใหม่ควรอยู่ แล้วแทรกที่ชั้นล่างสุดเสมอ
2. **โยนเหรียญ**: ถ้าออกหัว → ให้โหนดนี้ "ขึ้นไปอยู่ชั้นบนอีกชั้น" แล้วโยนเหรียญต่อ
3. ถ้าออกก้อย → หยุด
4. ผลคือ โหนดครึ่งหนึ่งอยู่แค่ชั้น 1, หนึ่งในสี่ขึ้นถึงชั้น 2, หนึ่งในแปดขึ้นถึงชั้น 3 ... ทำให้ "ทางด่วน" กระจายตัวสมดุลเองโดยบังเอิญ

**การลบ:** ค้นหาโหนดนั้น แล้วตัดมันออกจากทุกชั้นที่มันอยู่ (คล้ายลบใน linked list)

#### ข้อดี และข้อเสีย

| ข้อดี ✅                                           | ข้อเสีย ❌                                                                                                |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| ค้นหา แทรก ลบ เร็วโดยเฉลี่ย O(log n)              | ใช้ความจำเพิ่มสำหรับตัวชี้หลายชั้น (เฉลี่ยประมาณ 2 เท่าของลิสต์ปกติ)                                     |
| เขียนง่ายกว่า Balanced Tree (เช่น AVL, Red-Black) | ความเร็ว "โดยเฉลี่ย" ไม่ได้การันตีเสมอ เพราะขึ้นกับการสุ่ม (กรณีแย่สุดยังเป็น O(n) แต่เกิดขึ้นได้ยากมาก) |
| ข้อมูลเรียงลำดับอยู่แล้ว ไล่ดูตามลำดับได้         | ต้องมีตัวสุ่ม                                                                                            |

> 💡 **ปัญหาที่ยังเหลือ:** Skip List ช่วยเรื่องการค้นหา แต่ถ้าข้อมูลเป็นตารางใหญ่ๆ ที่ส่วนใหญ่เป็นค่าว่างหรือศูนย์ ล่ะ จะประหยัดความจำอย่างไร?
