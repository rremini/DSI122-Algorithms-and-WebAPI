Sparse Table คือโครงสร้างข้อมูลที่สร้างขึ้นเพื่อตอบคำถามแบบ **Range Query** 
(เช่น หาค่าต่ำสุดในช่วง<font color="#00b0f0"> L, R</font>) บน **array ที่ไม่มีการเปลี่ยนแปลงค่า (static/immutable array)** โดยสามารถตอบคำถามได้ในเวลา **O(1)** ต่อ query หลังจากเสียเวลา preprocessing ไปครั้งเดียว

### โครงสร้างและการแก้ปัญหาของ Sparse Table

![[Pasted image 20260926165816.png]]
**ปัญหาของการเก็บด้วยตารางปกติ:** หากนำตารางที่มีข้อมูลเบาบางไปจัดเก็บบนหน่วยความจำด้วยอาร์เรย์ 2 มิติขนาดใหญ่โดยตรง จะทำให้สิ้นเปลืองพื้นที่หน่วยความจำอย่างมากในการเก็บค่าว่าง
**การแทนที่ด้วย Linked List:** ตารางแบบ Sparse Table สามารถนำมารูปแบบใหม่โดยแทนที่ด้วย 
**ระบบของลิงก์ลิสต์ (System of Linked Lists)** เพื่อจัดเก็บเฉพาะช่องที่มีข้อมูลจริง
**การแทรกและการลบข้อมูล:** การใช้ลิงก์ลิสต์ช่วยให้การเพิ่ม (Insertion) หรือลบ (Deletion) ข้อมูลทำได้ง่าย เนื่องจากส่งผลกระทบเฉพาะส่วนในโหนดที่เชื่อมโยงกันเท่านั้น
**การเข้าถึงข้อมูล:** อาร์เรย์จะได้เปรียบกว่าลิงก์ลิสต์ตรงที่สามารถเข้าถึงข้อมูลแบบสุ่ม (Random accessing) ได้ทันที

## 2D-Arrays
![[Pasted image 20260923211531.png]]
แทนที่จะสร้างตาราง 2 มิติขนาดเต็ม ($300 \text{ วิชา} \times 8,000 \text{ คน} = 2,400,000 \text{ ช่อง}$) ระบบสามารถเปลี่ยนมาใช้อาร์เรย์ 2 มิติที่มีขนาดเล็กลงตามขอบเขตการใช้งานจริง:

<font color="#00b050">ข้อดี: </font>ยังคงความสามารถในการเข้าถึงข้อมูลแบบสุ่ม (Random accessing) ด้วย Index ของอาร์เรย์ได้อย่างรวดเร็ว
<font color="#d83931">ข้อจำกัด: </font>ยังมีช่องว่างเหลือทิ้งหากนักศึกษาลงเรียนไม่ครบโควตา และมีข้อจำกัดเรื่องขนาดคงที่ (Fixed size) หากมีนักศึกษาลงเรียนเกิน 8 วิชา หรือรายวิชามีคนเรียนเกิน 250 คน อาร์เรย์จะไม่สามารถรองรับได้ทันที
