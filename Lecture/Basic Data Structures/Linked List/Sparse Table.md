Sparse Table คือโครงสร้างข้อมูลที่สร้างขึ้นเพื่อตอบคำถามแบบ **Range Query** 
(เช่น หาค่าต่ำสุดในช่วง<font color="#00b0f0"> L, R</font>) บน **array ที่ไม่มีการเปลี่ยนแปลงค่า (static/immutable array)** โดยสามารถตอบคำถามได้ในเวลา **O(1)** ต่อ query หลังจากเสียเวลา preprocessing ไปครั้งเดียว

### โครงสร้างและการแก้ปัญหาของ Sparse Table

### Sparse Table = เมทริกซ์เบาบางด้วยโครงสร้างลิงก์ 
##### แนวคิดและปัญหาที่แก้
สมมติเรามีตารางขนาด 1,000 × 1,000 = **1,000,000 ช่อง** แต่มีข้อมูลจริงแค่ 50 ช่อง ที่เหลือเป็น 0 ทั้งหมด ถ้าเก็บด้วยอาร์เรย์ 2 มิติธรรมดา จะ **เปลืองความจำไปกับเลข 0 เกือบทั้งหมด**

> ทางแก้: **เก็บเฉพาะช่องที่มีค่าจริง** โดยใช้ลิงก์ลิสต์เชื่อมกัน

##### เปรียบเทียบกับชีวิตจริง

- **ที่นั่งในโรงหนังขนาดใหญ่ที่คนมาดูแค่ 20 คน**: แทนที่จะจดทุกที่นั่งว่า "ว่าง/ว่าง/ว่าง/..." เราจดแค่ "แถว D เลขที่ 5 มีคนนั่ง, แถว H เลขที่ 12 มีคนนั่ง" ก็พอ
- **สมุดโทรศัพท์**: จดเฉพาะคนที่เรารู้จัก ไม่ได้ทำตารางของทุกคนบนโลก

## ทำงานอย่างไร (ทีละขั้น)

**ตัวอย่างเมทริกซ์ 4×5 ที่ส่วนใหญ่เป็น 0:**

```python
        c0  c1  c2  c3  c4
  r0  [  0   0   7   0   0 ]
  r1  [  0   0   0   0   0 ]
  r2  [  3   0   0   0   9 ]
  r3  [  0   5   0   0   0 ]
```

### วิธีเก็บแบบง่าย: อาร์เรย์ของลิงก์ลิสต์ (หนึ่งลิสต์ต่อหนึ่งแถว)
แต่ละโหนดเก็บ 3 อย่าง: `คอลัมน์`, `ค่า`, และ `ตัวชี้ไปโหนดถัดไปในแถวเดียวกัน`

``` python
rows[0] → (col=2, val=7) → NIL
rows[1] → NIL                          ← แถวว่าง ไม่เปลืองอะไรเลย
rows[2] → (col=0, val=3) → (col=4, val=9) → NIL
rows[3] → (col=1, val=5) → NIL
```

**การอ่านค่าที่ตำแหน่ง (แถว r, คอลัมน์ c):**

1. ไปที่ `rows[r]` ใช้ลิสต์ของแถวนั้น
2. เดินไล่หาโหนดที่มี `col == c`
3. เจอ → คืนค่าในโหนดนั้น / ไม่เจอ → คืน **0** (เพราะช่องที่ไม่ได้เก็บคือ 0)

**การเขียนค่า:** ถ้ามีโหนดอยู่แล้ว ก็แก้ค่า ถ้ายังไม่มี ก็แทรกโหนดใหม่ในลิสต์ของแถวนั้น (แนะนำให้เรียงตามคอลัมน์)

> 📝 **เสริม:** ตำราบางเล่ม (เช่น Drozdek) ใช้ลิงก์ลิสต์ **ทั้งแถวและคอลัมน์** คือมีลิสต์ของแถวและลิสต์ของคอลัมน์ แล้วโหนดหนึ่งตัวจะอยู่ในสองลิสต์พร้อมกัน เพื่อให้เดินตามแถวหรือตามคอลัมน์ได้ทั้งคู่ ซึ่งซับซ้อนขึ้นแต่ยืดหยุ่นกว่า

### ข้อดี และข้อเสีย

|ข้อดี ✅|ข้อเสีย ❌|
|---|---|
|ประหยัดความจำมาก ถ้าข้อมูลส่วนใหญ่เป็นค่าว่าง/0|อ่านค่าช้ากว่าอาร์เรย์ (ต้องไล่ลิสต์ ไม่ใช่เข้าถึงตรงๆ ด้วย index)|
|ขนาดขึ้นกับ "จำนวนช่องที่มีค่า" ไม่ใช่ขนาดตาราง|แต่ละโหนดต้องเก็บตัวชี้และคอลัมน์เพิ่ม ถ้าตารางแน่น (ไม่ sparse) จะ **เปลืองกว่า** อาร์เรย์ปกติ|
|เหมาะกับข้อมูลเช่น กราฟที่มีเส้นเชื่อมน้อย, ตารางคะแนนที่ว่างเยอะ|โค้ดซับซ้อนกว่า|

#### 3B. Sparse Table = โครงสร้างสำหรับ Range Minimum Query (RMQ)

##### แนวคิดและปัญหาที่แก้

โจทย์: มีอาร์เรย์ตัวเลข และมีคำถามมากมายประเภท "ในช่วงตำแหน่ง L ถึง R ค่าที่ **น้อยที่สุด** คืออะไร?"

- ถ้าวนหาทุกครั้ง → ช้า O(n) ต่อคำถาม ถ้ามีคำถามล้านข้อก็ช้ามาก

**Sparse Table** แก้โดย **คำนวณคำตอบของช่วงขนาดพิเศษไว้ล่วงหน้า** แล้วตอบแต่ละคำถามได้ในทันที O(1)

##### เปรียบเทียบกับชีวิตจริง

**จดสถิติอุณหภูมิต่ำสุดล่วงหน้า:** แทนที่จะมีคนมาถามว่า "วันที่ 3–9 วันไหนเย็นสุด" แล้วนั่งไล่ดูทีละวัน เราจดล่วงหน้าไว้ว่า "ช่วง 1 วัน, 2 วัน, 4 วัน, 8 วัน... เริ่มจากแต่ละวัน ค่าต่ำสุดคือเท่าไร" พอมีคนถาม เราเอาสมุดมา **เปิดสองหน้า** แล้วเทียบกัน

##### ทำงานอย่างไร (ทีละขั้น)

กุญแจสำคัญ: ใช้ช่วงที่มีความยาวเป็น **เลขยกกำลังของ 2** (1, 2, 4, 8, ...)

ให้ `table[k][i]` = ค่าต่ำสุดของช่วงที่ **เริ่มที่ตำแหน่ง i ยาว 2^k ตัว**

**ตัวอย่าง:** `A = [5, 2, 4, 7, 1, 3, 6, 8]`

**ขั้นที่ 1: สร้างตาราง (ทำครั้งเดียว)**

- `k=0` (ช่วงยาว 1): ก็คือตัวอาร์เรย์เอง `[5, 2, 4, 7, 1, 3, 6, 8]`
- `k=1` (ช่วงยาว 2): เอาค่าต่ำสุดของ "สองครึ่งของ k=0" → `[2, 2, 4, 1, 1, 3, 6]`
- `k=2` (ช่วงยาว 4): เอาค่าต่ำสุดของ "สองครึ่งของ k=1" → `[2, 1, 1, 1, 1]`
- `k=3` (ช่วงยาว 8): → `[1]`

แต่ละชั้นสร้างจากชั้นก่อนหน้า: `table[k][i] = min( table[k-1][i], table[k-1][i + 2^(k-1)] )`

**ขั้นที่ 2: ตอบคำถาม (เช่น ค่าต่ำสุดของตำแหน่ง 1 ถึง 6)**

1. ความยาวช่วง = 6 → หาเลขยกกำลัง 2 ที่ใหญ่ที่สุดที่ **ไม่เกิน 6** ได้ 4 (k=2)
2. เอาช่วงยาว 4 ที่ **เริ่มจากซ้ายสุด** (ตำแหน่ง 1–4) → `table[2][1] = 1`
3. เอาช่วงยาว 4 ที่ **จบที่ขวาสุด** (ตำแหน่ง 3–6) → `table[2][3] = 1`
4. สองช่วงนี้ **ซ้อนทับกัน** ได้ ไม่เป็นไร เพราะการหาค่าต่ำสุดไม่ได้รับผลกระทบจากการนับซ้ำ
5. ตอบ `min(1, 1) = 1` ✅

เห็นไหมว่าตอบได้ด้วยการดูตาราง 2 ช่อง ไม่ต้องไล่ทีละตัวเลย!

##### ข้อดี และข้อเสีย

|ข้อดี ✅|ข้อเสีย ❌|
|---|---|
|ตอบคำถามช่วง (min/max) ได้ใน O(1)|ใช้ความจำ O(n log n)|
|เขียนง่าย|**แก้ไขค่าในอาร์เรย์ไม่ได้ง่ายๆ** (ต้องสร้างตารางใหม่) เหมาะกับข้อมูลที่ไม่เปลี่ยน|
|เหมาะกับคำถามเยอะๆ|ใช้ได้ดีกับ min/max/gcd แต่ **ใช้ไม่ได้กับผลรวม** ตรงๆ (เพราะการซ้อนทับจะนับซ้ำ)|
