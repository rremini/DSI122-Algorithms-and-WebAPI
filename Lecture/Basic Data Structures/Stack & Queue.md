## Stack
![[download.gif]]
### นิยาม 
Stack คือโครงสร้างข้อมูลเชิงเส้น (linear data structure) ที่เข้าถึงได้เพียง **ปลายด้านเดียว** ในการเก็บและดึงข้อมูล
### หลักการ LIFO (Last In, First Out)
ข้อมูลที่ใส่เข้าไป**หลังสุด**จะถูกนำออก**ก่อน** เปรียบเหมือนกองจานที่วางซ้อนกัน เรามักหยิบจานใบบนสุดที่เพิ่งวางออกมาก่อน

**การดำเนินการหลัก**

| การดำเนินการ | ความหมาย                                  |
| ------------ | ----------------------------------------- |
| `push(el)`   | ใส่ข้อมูล `el` ไว้บนสุดของ stack          |
| `pop()`      | นำข้อมูลบนสุดออกจาก stack (และคืนค่านั้น) |
| `topEl()`    | ดูค่าบนสุดของ stack **โดยไม่นำออก**       |
| `clear()`    | ล้างข้อมูลทั้งหมดใน stack                 |
| `isEmpty()`  | ตรวจสอบว่า stack ว่างหรือไม่              |
### ตัวอย่างการทำงาน (ตามสไลด์ "Series of Operations on a Stack")
ให้เริ่มจาก stack ว่าง (ในแต่ละบรรทัด ตัวเลขด้านซ้ายคือก้น stack และด้านขวาคือ top)

|ลำดับ|คำสั่ง|สถานะ Stack|หมายเหตุ|
|---|---|---|---|
|0|เริ่มต้น|`[ ]`|ว่าง|
|1|`push 5`|`[5]`|5 อยู่บนสุด|
|2|`push 9`|`[5, 9]`|9 อยู่บนสุด|
|3|`push 4`|`[5, 9, 4]`|4 อยู่บนสุด|
|4|`pop`|`[5, 9]`|นำ 4 ออก (4 เข้าทีหลังสุด จึงออกก่อน)|
|5|`topEl`|`[5, 9]`|คืนค่า 9 แต่ stack ไม่เปลี่ยนแปลง|
|6|`push 2`|`[5, 9, 2]`|2 อยู่บนสุด|

**ข้อสังเกตสำคัญ:** `pop` ทำให้ stack เปลี่ยน แต่ `topEl` เป็นเพียงการ "แอบดู" จึงไม่เปลี่ยนแปลง stack
**ตัวอย่างการใช้งานจริงของ Stack (ตามสไลด์)**

- การคำนวณกับจำนวนเต็มขนาดใหญ่ (long integers)
- การจับคู่เครื่องหมายวงเล็บ (delimiter matching)
- ประวัติหน้าเว็บที่เข้าชมของ Web browser (ปุ่ม Back)
- ลำดับการ Undo ในโปรแกรมประมวลผลคำ
- ลำดับการเรียกเมธอด/ฟังก์ชัน (call stack)
- การหาทางออกจากเขาวงกต (Maze) ซึ่งสไลด์ใช้ stack เก็บช่องที่ยังไม่ได้ไปเยือน

## Queue
![[download-1.gif]]
### นิยาม
Queue คือ "แถวรอ" ที่ขยายโดยการเพิ่มข้อมูลที่ **ท้ายแถว** และลดลงโดยการนำข้อมูลออกจาก **หัวแถว** ดังนั้น queue ใช้ **ทั้งสองปลาย** ปลายหนึ่งสำหรับเพิ่ม อีกปลายสำหรับนำออก

**หลักการ FIFO (First In, First Out):** ข้อมูลที่เข้ามา**ก่อน**จะถูกนำออก**ก่อน** เหมือนการต่อแถวซื้อของ ใครมาถึงก่อนได้รับบริการก่อน

### การดำเนินการหลัก

| การดำเนินการ  | ความหมาย                       |
| ------------- | ------------------------------ |
| `enqueue(el)` | ใส่ข้อมูล `el` ที่ท้ายคิว      |
| `dequeue()`   | นำข้อมูลตัวแรก (หัวคิว) ออก    |
| `firstEl()`   | ดูข้อมูลตัวแรก **โดยไม่นำออก** |
| `clear()`     | ล้างคิว                        |
| `isEmpty()`   | ตรวจสอบว่าคิวว่างหรือไม่       |

**ตัวอย่างการทำงาน** (หัวคิวอยู่ซ้าย ท้ายคิวอยู่ขวา)

|ลำดับ|คำสั่ง|สถานะ Queue|
|---|---|---|
|1|`enqueue 5`|`[5]`|
|2|`enqueue 9`|`[5, 9]`|
|3|`enqueue 7`|`[5, 9, 7]`|
|4|`dequeue`|`[9, 7]` (5 ออกก่อนเพราะเข้าก่อน)|
|5|`firstEl`|`[9, 7]` (คืนค่า 9 ไม่เปลี่ยนคิว)|
|6|`enqueue 2`|`[9, 7, 2]`|

**ตัวอย่างการใช้งานจริงของ Queue**
- แถวรอในปัญหาการจำลอง (simulation)
- การจัดตารางเวลาของโพรเซสโดยระบบปฏิบัติการ
- การเข้าถึงทรัพยากรที่ใช้ร่วมกัน

### เปรียบเทียบ Stack กับ Queue

|หัวข้อ|Stack|Queue|
|---|---|---|
|หลักการ|LIFO|FIFO|
|ปลายที่ใช้|ปลายเดียว (top)|สองปลาย (front และ rear)|
|เพิ่มข้อมูล|`push`|`enqueue`|
|นำข้อมูลออก|`pop`|`dequeue`|
|ดูค่าโดยไม่ลบ|`topEl`|`firstEl`|
|ตัวอย่างงาน|Undo, call stack|จัดคิวงานพิมพ์, CPU scheduling|

### การสร้าง Stack และ Queue (Implementation)
สไลด์เปรียบเทียบการสร้างด้วย 2 วิธี:
- **Array:** เก็บข้อมูลในอาร์เรย์และใช้ตัวแปรนับขนาด (`size`) หรือตัวชี้ตำแหน่ง ข้อดีคือเรียบง่าย ข้อเสียคือขนาดคงที่ (Figure 4-6)
- **Linked List:** ใช้ `head` (และ `tail` สำหรับ queue) ชี้ไปยังโหนดที่เชื่อมกัน ขนาดยืดหยุ่นตามข้อมูล

**Queue แบบ Array (Circular Queue):** ถ้าใช้อาร์เรย์ธรรมดา เมื่อ `dequeue` ไปเรื่อย ๆ จะมีช่องว่างด้านหน้าที่ใช้ไม่ได้ สไลด์จึงใช้แนวคิด **คิววงกลม** (Figure 4-9, 4-10) ดังนี้

- ตัวแปร `first` และ `last` ชี้หัวและท้ายคิว
- เมื่อ `last` ถึงปลายอาร์เรย์ (`size-1`) ให้วนกลับไปช่อง `0` ถ้ายังมีที่ว่าง
- คิวว่างเมื่อ `first == -1`
- คิวเต็มเมื่อ `first == 0 && last == size-1` หรือ `first == last + 1`

**Priority Queue (คิวลำดับความสำคัญ):** ข้อมูลถูก dequeue ตาม **ระดับความสำคัญ** ร่วมกับตำแหน่งในคิว ไม่ใช่ตามลำดับเข้ามาอย่างเดียว ใช้เมื่อต้องการให้บางงานถูกประมวลผลก่อนโดยไม่กระทบระบบโดยรวม

### การบวกเลขจำนวนเต็มขนาดใหญ่ด้วย Stack

#### แนวคิดและเหตุผลที่ใช้ Stack
**ปัญหา:** ชนิดข้อมูลจำนวนเต็มทั่วไป (เช่น `int`, `long`) มีขนาดจำกัด หากต้องบวกเลขที่ยาวมาก ๆ เกินกว่าที่ชนิดข้อมูลรองรับ เราต้องเก็บเลขเป็น **หลัก ๆ (digit by digit)** แล้วบวกทีละหลักเหมือนที่เราบวกเลขบนกระดาษ

**ทำไมต้องใช้ Stack?** เพราะการบวกด้วยมือต้องเริ่มจาก **หลักหน่วย (ขวาสุด)** ไปทางซ้าย แต่เราอ่านและเก็บตัวเลขจาก **ซ้ายไปขวา** (หลักที่มากที่สุดก่อน)
- ตอนเก็บตัวเลข ให้ `push` ทีละหลักจากซ้ายไปขวา
- หลักหน่วยซึ่งเป็นตัวสุดท้ายที่ push จะอยู่ **บนสุด** ของ stack
- ตอน `pop` จึงได้หลักหน่วยออกมาก่อน (LIFO) ซึ่งตรงกับลำดับที่ต้องการบวกพอดี
- ผลลัพธ์แต่ละหลักที่คำนวณได้ก็ `push` เก็บลง **result stack** เมื่อบวกเสร็จ หลักที่มากที่สุดจะอยู่บนสุด เมื่อ `pop` ออกมาอ่านจะได้ตัวเลขเรียงถูกต้องจากซ้ายไปขวา

**สิ่งที่ต้องใช้**
- `operandStack1` เก็บเลขตัวแรก
- `operandStack2` เก็บเลขตัวที่สอง
- `resultStack` เก็บผลลัพธ์
- ตัวแปร `carry` (ตัวทด) ค่าเริ่มต้น 0

#### 2.2 อัลกอริทึม (Pseudocode)

```
carry = 0
while (operandStack1 หรือ operandStack2 ยังไม่ว่าง)
    a = operandStack1 ว่าง ? 0 : pop(operandStack1)
    b = operandStack2 ว่าง ? 0 : pop(operandStack2)
    sum = a + b + carry
    push(resultStack, sum mod 10)   // หลักที่เก็บ
    carry = sum div 10              // ตัวทดไปหลักถัดไป
if carry > 0
    push(resultStack, carry)
```

สไลด์ (Figure 4-3) แสดงตัวทดโดยแยกเลข "1,7" หรือ "1,3" ซึ่งหมายถึงตัวทด 1 และหลักผลลัพธ์ 7 หรือ 3 ตามลำดับ

#### 2.3 ตัวอย่าง: 592 + 3,784

**ขั้นที่ 0: เตรียม Stack**

push ตัวเลขทีละหลักจากซ้ายไปขวา (บนสุดของ stack คือหลักหน่วย)

- `operandStack1` (592): ก้น→บน = `5, 9, 2` (top = 2)
- `operandStack2` (3784): ก้น→บน = `3, 7, 8, 4` (top = 4)
- `resultStack`: ว่าง
- `carry = 0`

**ขั้นที่ 1: หลักหน่วย**

- pop `2` จาก Stack1 และ `4` จาก Stack2
- sum = 2 + 4 + 0 = **6**
- push `6` ลง resultStack, carry = 0

|Stack1|Stack2|Result|carry|
|---|---|---|---|
|`5, 9`|`3, 7, 8`|`6`|0|

**ขั้นที่ 2: หลักสิบ**

- pop `9` และ `8`
- sum = 9 + 8 + 0 = **17**
- push `7` (17 mod 10), carry = 1 (17 div 10)

|Stack1|Stack2|Result|carry|
|---|---|---|---|
|`5`|`3, 7`|`6, 7`|1|

**ขั้นที่ 3: หลักร้อย**

- pop `5` และ `7`
- sum = 5 + 7 + 1 (ตัวทด) = **13**
- push `3`, carry = 1

|Stack1|Stack2|Result|carry|
|---|---|---|---|
|ว่าง|`3`|`6, 7, 3`|1|

**ขั้นที่ 4: หลักพัน**

- Stack1 ว่างแล้ว จึงใช้ค่า 0 แทน, pop `3` จาก Stack2
- sum = 0 + 3 + 1 = **4**
- push `4`, carry = 0

|Stack1|Stack2|Result|carry|
|---|---|---|---|
|ว่าง|ว่าง|`6, 7, 3, 4`|0|

**ขั้นที่ 5: อ่านผลลัพธ์**

ทั้งสอง operand stack ว่างและ carry = 0 จึงเสร็จสิ้น `resultStack` (ก้น→บน) คือ `6, 7, 3, 4` เมื่อ `pop` ออกมาทีละตัวจะได้ **4, 3, 7, 6** อ่านเป็น **4376**

**ตรวจสอบ:** 592 + 3,784 = 4,376 ✓ ตรงกับ Figure 4-3

#### 2.4 สรุปประเด็นสำคัญ

- Stack ช่วย **กลับลำดับ** ของหลักตัวเลข ทำให้เข้าถึงหลักหน่วยก่อนได้โดยธรรมชาติ
- เมื่อ stack ใดหมดก่อน ให้ถือว่าหลักที่เหลือเป็น **0**
- ตัวทด (carry) ต้องนำไปบวกในหลักถัดไป และหากเหลือตัวทดหลังหลักสุดท้าย ให้ push เป็นหลักใหม่ (เช่น 999 + 1 = 1000)
- วิธีนี้ไม่จำกัดความยาวของตัวเลข ขึ้นกับหน่วยความจำเท่านั้น
