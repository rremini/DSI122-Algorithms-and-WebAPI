**Closest-Pair Problem** (ปัญหาคู่จุดที่ใกล้ที่สุด) คือโจทย์ทางเรขาคณิตเชิงคำนวณที่มุ่งหาจุด 2 จุดที่มีระยะห่างสั้นที่สุดจากจุดทั้งหมด $n$ จุดบนระนาบ 2 มิติ (พิกัด $x, y$ แบบแกนกราฟที่เรียนในวิชาคณิตศาสตร์)
![[Pasted image 20260927144757.png]]
ลองนึกภาพง่าย ๆ เหมือนเราเอาปากกาจุดลงบนกระดาษกราฟ 100 จุดแบบสุ่ม ปัญหา Closest-Pair คือภารกิจที่ให้เรามองหาว่า **จุดคู่ไหนอยู่ใกล้กันที่สุด** นั่นเอง

### Closest-Pair ไม่ใช่อัลกอริทึม แต่เป็น<font color="#d99694"> ตัวโจทย์ปัญหา</font>
ส่วน Brute Force และ Divide and Conquer คือ**แนวทางหรือวิธีคิดในการแก้โจทย์**
- **Brute Force:** ใช้เป็นตัวอย่างกรณีศึกษาของการแก้ปัญหาโครตกำปั้นทุบดิน <font color="#d99694">คิดง่ายแต่ช้ามากๆๆ</font> โดยการคำนวณระยะห่างระหว่างจุดทุกคู่
- **Divide and Conquer:** ใช้เป็นตัวอย่างการแก้ปัญหาด้วยการแบ่งแยกและเอาชนะ โดยการแบ่งระนาบจุดออกเป็นฝั่งซ้าย-ขวา แล้วผสานคำตอบเพื่อเพิ่มประสิทธิภาพ <font color="#92d050">จะช่วยแก้ปัญหาเดิมได้รวดเร็วและฉลาดกว่า</font>

## 1. วิธี Brute Force <font color="#de7802">—</font> O(N²)
คำนวณระยะห่างของทุกคู่จุดที่เป็นไปได้ แล้วเลือกคู่ที่ระยะน้อยที่สุด
![[Pasted image 20260927141230.png]]

```
สำหรับ i = 1 ถึง n-1
    สำหรับ j = i+1 ถึง n
        d = sqrt((xi-xj)² + (yi-yj)²)
        ถ้า d < dmin: อัปเดต dmin, index1, index2
```

จำนวนการเปรียบเทียบคือ C(n,2) = n(n-1)/2 คู่ ⇒ **Θ(n²)** — เรียบง่าย เขียนง่าย รับประกันความถูกต้อง แต่เมื่อ n ใหญ่ขึ้น (เช่นหลักแสนหรือล้านจุด) จะช้ามาก

## 2. วิธี Divide and Conquer <font color="#de7802">—</font> O(N log N)
![[Pasted image 20260927144423.png]]
แนวคิดคือแบ่งปัญหาใหญ่ให้เล็กลงแล้วรวมผลลัพธ์ ขั้นตอนหลัก:
1. **เรียงจุดตามพิกัด x** (ทำครั้งเดียว O(n log n))
2. **Divide**: แบ่งจุดออกเป็นสองฝั่งซ้าย-ขวาด้วยเส้นแนวตั้ง x = mid
3. **Conquer**: หาคู่จุดที่ใกล้ที่สุดในฝั่งซ้าย (dL) และฝั่งขวา (dR) แยกกัน แล้วให้ d = min(dL, dR)
4. **Combin**: ปัญหาคือคู่จุดที่ใกล้ที่สุดจริง ๆ อาจ "คร่อม" เส้นแบ่งกลาง คืออยู่คนละฝั่งแต่ใกล้กันมากกว่า dL หรือ dR ก็ได้ ตรงนี้คือที่มาของ **แถบกั้นกลาง (boundary strip / middle strip)**

#### การจัดการ Boundary Strip
- สร้างแถบแนวตั้งกว้าง 2D รอบเส้นกลาง (d คือค่า min ที่ได้จากขั้นตอน 3) คือเก็บเฉพาะจุดที่ |x - xmid| < d
- เรียงจุดในแถบนี้ตามพิกัด y
- ประเด็นสำคัญ (ทฤษฎีบทที่ทำให้อัลกอริทึมนี้เร็ว): สำหรับแต่ละจุดในแถบ ไม่จำเป็นต้องเทียบกับทุกจุดอื่นในแถบ แต่เทียบกับจุดถัดไปใน**ลำดับ y เพียงประมาณ 7-8 จุดถัดไป**ก็เพียงพอ เพราะสามารถพิสูจน์ทางเรขาคณิตได้ว่าในสี่เหลี่ยม 2d × d นั้นมีจุดที่เป็นไปได้ (ห่างกันไม่เกิน d) อยู่ได้อย่างมากแค่จำนวนคงที่จุดเท่านั้น (ไม่งั้นจะขัดกับสมมติฐานว่า d คือระยะที่น้อยที่สุดในแต่ละฝั่งอยู่แล้ว)
- เพราะข้อจำกัดนี้ ขั้นตอนรวมผลจึงทำได้ใน **O(n)** ไม่ใช่ O(n²)

**สมการเวลาที่ได้:** T(n) = 2T(n/2) + O(n) ⇒ ตาม Master Theorem ได้ **T(n) = O(n log n)**

## 3. เปรียบเทียบข้อดี-ข้อเสีย

| ประเด็น                  | Brute Force O(n²)                                                       | Divide & Conquer O(n log n)                                                |
| ------------------------ | ----------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| ความง่ายในการเขียน/ดีบัก | ✅ เขียนง่าย เข้าใจง่าย ดีบักง่าย เหมาะกับตอนเริ่มเรียนเขียนโปรแกรม      | ✅ เร็วกว่ามากเมื่อมีจุดจำนวนมาก เหมาะกับงานจริงที่ต้องรองรับข้อมูลขนาดใหญ่ |
| ประสิทธิภาพเมื่อ n เล็ก  | เร็วกว่าจริง (overhead น้อย)                                            | มี overhead จากการเรียกซ้ำ/เรียงลำดับ ทำให้ช้ากว่าเมื่อ n เล็ก             |
| ประสิทธิภาพเมื่อ n ใหญ่  | พอจุดเยอะขึ้นมาก ๆ จะช้าจนใช้งานจริงไม่ได้เลย                           | จำเป็นและคุ้มค่า                                                           |
| หน่วยความจำ              | O(1) เพิ่มเติม                                                          | ต้องใช้พื้นที่สำหรับ recursion และอาร์เรย์ช่วย (โดยทั่วไป O(n))            |
| ในทางปฏิบัติ             | มักใช้เป็น base case เมื่อจำนวนจุดในการเรียกซ้ำเหลือน้อย (เช่น ≤ 3 จุด) | เป็นทางเลือกมาตรฐานในไลบรารีที่ต้องรองรับข้อมูลขนาดใหญ่                    |

## 5. ตัวอย่างโค๊ด JavaScript
```JavaScript
// =====================================================
// 🎯 ปัญหา: หาคู่จุดสองจุดที่อยู่ "ใกล้กันที่สุด"
// วิธีนี้คือ "Brute Force" แปลว่า "ลุยตรง ๆ" คือ
// เช็กทุกคู่ที่เป็นไปได้ ไม่มีเทคนิคพิเศษอะไรเลย
// =====================================================

// ฟังก์ชันช่วย: คำนวณระยะห่างระหว่างจุด 2 จุด
// โดยใช้สูตรพีทาโกรัส (ทฤษฎีบทพีทาโกรัสที่เราเรียนกัน!)
// distance = sqrt( (x1-x2)^2 + (y1-y2)^2 )
function findDistance(pointA, pointB) {
  const diffX = pointA.x - pointB.x;
  const diffY = pointA.y - pointB.y;
  return Math.sqrt(diffX * diffX + diffY * diffY);
}

// ฟังก์ชันหลัก: หาคู่จุดที่ใกล้กันที่สุดแบบ Brute Force
function bruteForceClosestPair(points) {
  // เริ่มต้นด้วยการสมมติว่าระยะที่น้อยที่สุด "ยังไม่มี"
  // เลยตั้งเป็นค่าอนันต์ไปก่อน (จะได้แน่ใจว่าคู่แรกที่เจอ
  // จะถูกบันทึกไว้แน่นอน)
  let shortestDistance = Infinity;
  let bestPair = null;

  // วนลูปคู่แรก (i) ตั้งแต่จุดแรกถึงจุดรองสุดท้าย
  for (let i = 0; i < points.length - 1; i++) {
    // วนลูปคู่ที่สอง (j) เริ่มจากจุดถัดจาก i ไปเรื่อย ๆ
    // (เริ่มจาก i+1 เพื่อไม่ให้เช็กคู่ซ้ำ เช่น (A,B) กับ (B,A))
    for (let j = i + 1; j < points.length; j++) {
      const currentDistance = findDistance(points[i], points[j]);

      // ถ้าคู่นี้ใกล้กว่าคู่ที่เคยเจอมาก่อน ก็อัปเดตค่าที่ดีที่สุด
      if (currentDistance < shortestDistance) {
        shortestDistance = currentDistance;
        bestPair = [points[i], points[j]];
      }
    }
  }

  return { shortestDistance, bestPair };
}

// =====================================================
// 🧪 ลองใช้งานกันดู!
// สมมติว่านี่คือตำแหน่งของเครื่องบิน 6 ลำบนจอเรดาร์
// =====================================================
const airplanes = [
  { x: 10, y: 20, name: "Plane A" },
  { x: 15, y: 25, name: "Plane B" },
  { x: 100, y: 200, name: "Plane C" },
  { x: 12, y: 22, name: "Plane D" }, // ลำนี้อยู่ใกล้ Plane A และ B มาก!
  { x: 300, y: 300, name: "Plane E" },
  { x: 50, y: 60, name: "Plane F" },
];

const result = bruteForceClosestPair(airplanes);

console.log("เครื่องบินที่เข้าใกล้กันที่สุดคือ:");
console.log(result.bestPair[0].name, "กับ", result.bestPair[1].name);
console.log("ระยะห่าง:", result.shortestDistance.toFixed(2), "หน่วย");

// =====================================================
// 💡 แล้ว Divide and Conquer จะช่วยปรับปรุงตรงไหน?
// =====================================================
// แทนที่จะวนลูปสองชั้นเช็กทุกคู่ (ซึ่งช้ามากถ้าจุดเยอะ)
// Divide and Conquer จะทำแบบนี้แทน:
//
// 1) เรียงจุดทั้งหมดตามแกน x ก่อน (ทำแค่ครั้งเดียว)
// 2) แบ่งจุดเป็นสองฝั่งซ้าย-ขวา (เหมือนตัดห้องเป็นสองฝั่ง)
// 3) เรียกฟังก์ชันตัวเอง (เรียกว่า "recursion") เพื่อหาคู่ที่ใกล้
//    ที่สุดในแต่ละฝั่งแยกกัน จนกว่าแต่ละฝั่งจะเหลือจุดน้อยมาก
//    (พอน้อยแล้วค่อยใช้ brute force กับกลุ่มเล็ก ๆ นั้น)
// 4) เช็กเพิ่มอีกนิดเดียวตรง "แถบแคบ ๆ" กลางเส้นแบ่ง เผื่อมีคู่ที่
//    อยู่คนละฝั่งแต่ดันใกล้กันกว่าที่เจอในแต่ละฝั่ง
//
// ผลลัพธ์คือ: จากที่ต้องเช็กเกือบทุกคู่ (ช้าแบบ n²)
// จะเหลือแค่เช็กบางส่วนเท่านั้น (เร็วแบบ n log n)
// ยิ่งจุดเยอะเท่าไหร่ ความต่างยิ่งเห็นชัดมากขึ้นเท่านั้น!
```
