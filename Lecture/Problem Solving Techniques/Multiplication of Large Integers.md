### ทำไมต้องมีอัลกอริทึมนี้
เวลาคูณเลขสองตัวที่มีหลายหลัก (**Large integers** - จำนวนเต็มที่มีจำนวนหลักมาก เช่นใช้ในการเข้ารหัสข้อมูล) ด้วยวิธีคูณแบบที่เรียนมาตั้งแต่ประถม ซึ่งใช้วิธีการแบบ [[Brute Force]] เราจะต้องคูณทีละหลักคูณทีละหลัก ถ้าเลขแต่ละตัวมี n หลัก จะต้องทำการคูณหลักเดียว (one-digit multiplication) ทั้งหมด n² ครั้ง

> นั่นคือ **Time complexity** ของวิธีคูณแบบปกติคือ **O(n²)**![[Pasted image 20260922224339.png|390]]
<font color="#7f7f7f">Time Complexity: ไว้วัดว่าเวลาทำงานโตขึ้นเร็วแค่ไหนเทียบกับขนาดข้อมูล</font>

Anatoly Karatsuba นักคณิตศาสตร์ชาวรัสเซีย ค้นพบว่าเราสามารถคูณเลขขนาดใหญ่ได้เร็วกว่านี้ โดยใช้แนวคิด [[Divide & Conquer]] (แบ่งแยกและเอาชนะ — คือการแบ่งปัญหาใหญ่ออกเป็นปัญหาย่อยที่เล็กกว่าและมีลักษณะเหมือนปัญหาเดิม แล้วนำคำตอบของปัญหาย่อยมารวมกันเป็นคำตอบของปัญหาใหญ่)

### แนวคิดพื้นฐาน — แบ่งเลขออกเป็นสองส่วน
สมมติเรามีเลขสองตัวที่มี n หลักเท่ากัน คือ a และ b เราแบ่งแต่ละตัวออกเป็นสองครึ่ง (ครึ่งซ้ายและครึ่งขวา)
```
a = a1·10^(n/2) + a0
b = b1·10^(n/2) + b0
```

โดย a1, b1 คือครึ่งหลักสูง (high-order half) และ a0, b0 คือครึ่งหลักต่ำ (low-order half)

ผลคูณ a×b เขียนใหม่ได้เป็น:

```
c = a·b = c2·10^n + c1·10^(n/2) + c0
```

โดยที่:
- **c2 = a1·b1**
- **c0 = a0·b0**
- **c1 = a1·b0 + a0·b1**

### วิธีแรกแบบ Divide & Conquer <font color="#d83931">(ยังไม่ใช่ Karatsuba)</font>
ถ้าคำนวณตรง ๆ ตามสูตรข้างบน เราต้องคูณเลขย่อย 4 ครั้ง คือ a1·b1, a1·b0, a0·b1, a0·b0

เขียนเป็น **Recurrence Relation** (สมการที่บอกว่าเวลาทำงานของปัญหาขนาด n ขึ้นกับเวลาทำงานของปัญหาขนาดเล็กกว่า) สำหรับจำนวนครั้งของการคูณหลักเดียว M(n) ได้ว่า
```
M(n) = 4·M(n/2),   M(1) = 1
```

แก้สมการนี้ได้ M(n) = n² — **ยังคงเป็น O(n²) เท่าเดิม ซึ่งไม่ได้เร็วขึ้นเลย** เพราะแค่แบ่งปัญหาแต่จำนวนการคูณย่อยไม่ได้ลดลง

---
### Karatsuba — <font color="#ffc000">ลดจาก 4 ครั้งเหลือ 3 ครั้ง</font>
จุดที่ Karatsuba ฉลาดคือ เขาสังเกตว่า **ไม่จำเป็นต้องคูณ a1·b0 และ a0·b1 แยกกัน** เราสามารถหาผลรวม (a1·b0 + a0·b1) ได้จากการคูณเพียงครั้งเดียว โดยอาศัยสูตรพีชคณิตนี้

```
(a1 + a0)·(b1 + b0) = a1·b1 + a1·b0 + a0·b1 + a0·b0
                    = c2 + (a1·b0 + a0·b1) + c0
```

ดังนั้น

```
c1 = (a1 + a0)·(b1 + b0) − c2 − c0
```

สรุปแล้ว Karatsuba ต้องการเพียง **3 การคูณ** ของเลขที่มีขนาดครึ่งหนึ่ง คือ

| ตัวแปร | สูตร                        |
| ------ | --------------------------- |
| c2     | a1 × b1                     |
| c0     | a0 × b0                     |
| c1     | (a1+a0) × (b1+b0) − c2 − c0 |

### Recurrence relation ของ Karatsuba 
```
M(n) = 3·M(n/2) + Θ(n),   M(1) = 1
```

เมื่อแก้สมการนี้ (ด้วย Master Theorem หรือวิธี backward substitution) จะได้

```
M(n) = Θ(n^(log₂3)) ≈ Θ(n^1.585)
```

เพราะ log₂3 ≈ 1.585 นี่คือ **efficiency class** (ระดับความซับซ้อน) ที่ดีกว่า O(n²) อย่างชัดเจนเมื่อ n มีค่ามาก — ยิ่งเลขยิ่งยาว (n ยิ่งใหญ่) Karatsuba ยิ่งเร็วกว่าวิธีปกติมาก

### ตัวอย่างคำนวณทีละขั้น
<font color="#e36c09">ตัวอย่างที่ 1:</font> 12 × 34
- แบ่ง: a1=1, a0=2 (จาก 12) และ b1=3, b0=4 (จาก 34)
- c2 = a1·b1 = 1×3 = **3**
- c0 = a0·b0 = 2×4 = **8**
- c1 = (a1+a0)(b1+b0) − c2 − c0 = (1+2)(3+4) − 3 − 8 = 21 − 11 = **10**
- รวม: c = c2·10² + c1·10¹ + c0 = 300 + 100 + 8 = **408**
- <font color="#00b050">ตรวจคำตอบ: </font>12 × 34 = 408 <font color="#00b050">✓</font>

<font color="#e36c09">ตัวอย่างที่ 2:</font> 2135 × 4014
- แบ่งครึ่ง: a1=21, a0=35 (จาก 2135) และ b1=40, b0=14 (จาก 4014)
- c2 = a1·b1 = 21×40 = **840**
- c0 = a0·b0 = 35×14 = **490**
- c1 = (21+35)(40+14) − c2 − c0 = 56×54 − 840 − 490 = 3024 − 1330 = **1694**
- รวม: c = c2·10⁴ + c1·10² + c0 = 8,400,000 + 169,400 + 490 = **8,569,890**
- <font color="#00b050">ตรวจคำตอบ: </font>2135 × 4014 = 8,569,890 <font color="#00b050">✓</font>

### Pseudocode
```
function Karatsuba(x, y):
    if x < 10 or y < 10:          # base case
        return x * y
    n = max(digits(x), digits(y))
    half = n // 2
    a1, a0 = split(x, half)       # x = a1 * 10^half + a0
    b1, b0 = split(y, half)

    c2 = Karatsuba(a1, b1)
    c0 = Karatsuba(a0, b0)
    c1 = Karatsuba(a1 + a0, b1 + b0) - c2 - c0

    return c2 * 10^(2*half) + c1 * 10^half + c0
```

> [!tip] ประเด็นสำคัญที่ควรจำ
> เคล็ดลับของ Karatsuba ไม่ได้อยู่ที่การแบ่งปัญหา (Divide) แต่อยู่ที่การใช้พีชคณิตฉลาด ๆ เพื่อ**ลดจำนวนครั้งของการคูณย่อยจาก 4 เหลือ 3** ซึ่งทำให้ Recursion tree มีกิ่งน้อยลง และทำให้ความซับซ้อนโดยรวมลดลงจาก O(n²) เหลือ O(n^1.585)
